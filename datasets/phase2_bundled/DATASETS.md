## 2. Length and register profile — read this before trusting the extra data

| Dataset | input words (p50) | output words (mean / p50) | opens `হেলো` |
|---|---|---|---|
| **`train.parquet`** *(competition)* | 65 | **99.7 / 93** | **76.4%** |
| `dev.parquet` | 66 | 100.2 / 93 | — |
| `test.parquet` | 64 | *(no targets)* | — |
| `icliniq` | 61 | 82.2 / 77 | **0.0%** |
| `doctor_qa_bangla` | 13 | 51.9 / 41 | **0.0%** |
| `genmedgpt` | 20 | 36.3 / 31 | **0.0%** |

### The extra 17,172 rows are OFF-REGISTER, and you must decide deliberately whether to use them

**Not one of the 17,172 extra rows opens with `হেলো`** — against **76.4%** of the competition's
own answers. They are also much shorter: GenMedGPT's median answer is **31 words** against the
competition's **93**.

This is the *same measurement* that got a 166,193-row corpus (`ai_medical_chatbot`) excluded
from this project earlier — it opened `হাই`/`হ্যালো` 70% of the time instead of `হেলো`, and
off-register content is precisely what a lexical-overlap metric punishes.

**Why they are still bundled, and why this is a genuine judgment call rather than an oversight:**

- **Phase 2 is judged by an LLM on clinical quality, not by token overlap.** Register matters far
  less there than it does on the Phase 1 leaderboard. Clinical *diversity* — real consultations
  from a different site, and genuinely native Bengali — is exactly what should generalize.
- They are the only non-HealthCareMagic real dialogue available, and `doctor_qa_bangla` is the
  only natively-authored Bengali source in the entire project.
- **Their short length is a real risk**: mixed in at ~14% of rows, they pull the model's output
  length distribution down, and both Token F1 and ROUGE-L have precision terms that punish
  length mismatch in either direction.

**This is exactly what experiment X4 exists to settle.** X4 trains on `plain_core_only`
(competition rows only) versus the full mix, at identical config. **Run it. Do not assume more
data is better** — this project has already measured extra data *hurting* for this precise
reason. If X4 comes out inside the 0.0044 noise floor, prefer the smaller dataset: fewer external
sources to disclose, faster training, no register dilution.

## 3. Files generated by the build scripts

Neither exists until you run the scripts; both are reproducible and safe to delete.

```
python shared/build_index.py     # → data/_index/
python shared/build_data.py      # → data/plain/  data/rag/  data/plain_core_only/
```

| Path | Contents |
|---|---|
| `_index/pool_embeddings.npy` | (118,912 × 768) float32, L2-normalized, `multilingual-e5-base` |
| `_index/pool_metadata.parquet` | the 118,912-row pool, `id · source · input · output` |
| `_index/MANIFEST.json` | embed model, params, source counts, leak-assert result |
| `plain/{train,dev,test}.parquet` | 118,912 / 300 / 1,000 — question → answer |
| `rag/{train,dev,test}.parquet` | same rows + a retrieved reference case prepended; dev/test also carry `ref_input` / `ref_output` for the copy-check |
| `plain_core_only/…` | **101,740** — competition rows only (X4) |
| `plain_core_plus_icliniq/…` | **109,061** — competition + iCliniq (D1) |
| `plain_core_plus_genmedgpt/…` | **106,940** — competition + GenMedGPT (D2) |
| `plain_core_plus_doctor_qa_bangla/…` | **106,391** — competition + doctor_qa_bangla (D3) |

D1–D3 decompose X4's bundled comparison so a negative result can be attributed to a specific
source rather than guessed at. **They run on `A_mT5_base` (seq2seq) and `B_Qwen35_2B` (decoder)
as a cross-check** — agreement means the verdict is architecture-independent and
`C_BanglaAI_17B` inherits it; disagreement is itself a finding. See `../EXPERIMENTS.md`.

**The retrieval pool is 118,912 rows** = 101,740 + 17,172. Verified by running the assembly.

## 4. Leak safety — verified, not assumed

The frozen split is **seed 42, 5,000 dev rows**. Every number in this project rests on it.

| Check | Result |
|---|---|
| dev ids present in the training pool | **0 of 5,000** |
| test ids present in the training pool | **0 of 1,000** |
| `healthcaremagic` rows in `extra_sources.parquet` | **0** — excluded at extraction |
| `given_train` rows (competition split duplicated back in) | **0** |

Both `build_index.py` and `build_data.py` re-assert these at runtime. **Do not disable them.**
`build_data.py` additionally enforces that no row may retrieve *itself* or a near-duplicate
(cosine > 0.97) as its own RAG reference — which would paste the answer into the input.

**`dev.parquet` and `test.parquet` are for evaluation only. Never train on them.** Rules §8
makes training on test inputs a disqualifying offence.

## 5. What is deliberately NOT bundled

| Not here | Rows | Why |
|---|---|---|
| `healthcaremagic` | 106,117 | Our own re-translation of the *same cases* the competition already provides in the organizers' translation — redundancy plus a competing lexical fingerprint, no new medical information |
| `ai_medical_chatbot` | 166,193 | **Measured off-register** (`হাই`/`হ্যালো` 70.06% vs references' `হেলো` 76.37%) |
| `alpaca_health` | 1,021 | Its "medical" keyword filter matched homographs — ≥6.4% is computing/economics content |
| `disease_db` | 796 | Bullet lists, no doctor voice |
| `mts_dialog` | 3,503 | Inverse task: clinical note → doctor's *opening line* |
| NEW_DATASETS_D1 | 277,095 | 68% exam MCQ; translation damaged clinical detail (`prostatic` → `প্রিজম্যাটিক`, a B12 dose rendered in picograms instead of micrograms) |
| MedAidDialog / IndicMedDialog | — | LLM-generated then machine-translated — two synthetic fingerprints. IndicMedDialog is also CC BY-NC-**ND**, which plausibly forbids fine-tuning |

Full reasoning for each: `../DATA_GUIDE.md`.
